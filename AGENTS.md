# Project agent memory

batsim is an ERCOT-only residential battery fleet simulator written in Rust: physics-faithful virtual Tesla Powerwall 2/3, Enphase IQ Battery, SolarEdge Home Battery, and sonnen systems. The OpenAPI-first HTTP API for dispatch-strategy testing shipped in M2 (see Implementation state). The authoritative build brief for upcoming work is `docs/residential-battery-fleet-simulator-spec.md` - follow it; do not duplicate its content here. Human-facing docs live in `docs/` (architecture, device registry, physics models, testing); runnable usage demos live in `crates/batsim-core/examples/`.

## Implementation state

M1 (core engine + registry, spec 0.2) is complete on main: crates `batsim-core` (tick engine, battery/inverter/load/PV physics, home pipeline) and `batsim-registry` (21-entry JSON catalog under `registry/`, integrity-checked loader, HomeSystem composer). M2 (API skeleton, spec Part C) is complete on main: crates `batsim-server` (axum shell, utoipa OpenAPI at /openapi.json + Swagger UI, homes/fleets/scenarios/sim/dispatch/telemetry routes, engine thread over a command channel, static+synthetic price feed behind a replay-ready interface) and `batsim-cli` (`batsimctl` mirroring the API). M3 (ERCOT backtesting, spec Part D) is complete on branch `fm/batsim-m3`: crate `batsim-ercot` (`PriceSource` trait with `Replay` over partitioned Parquet and `SyntheticPriceGenerator` stress generator; settlement engine with per-interval energy/AS/4CP/retailer-margin ledgers; versioned rules in `config/ercot_rules.v2025.toml`; `batsim-ercot-ingest` binary normalizing real ERCOT MIS yearly reports - RTM SPP 13061, DAM SPP 13060, AS MCPC 13091 - into Parquet under `<data_dir>/ercot`, verification log in the crate README), `/v1/backtests` API (start a replay run for fleet + CPT day, per-interval settlement streamed as `settlement`/`run_finished` events over the existing SSE/WS telemetry path, final SettlementReport endpoint), `batsimctl backtests`, and a worked example in `examples/ercot-scarcity-backtest/` (real 2023-08-17 scarcity day, baseline vs heuristic P&L). M4+ (outages, thermal, degradation, vendor mimicry, live adapter) has not started.

The 3D web UI vertical slice lives in `web/` (Vite + React + TS, MapLibre + three.js; build brief `docs/batsim-3d-ui-spec.md`): CartoDB Dark Matter tiles under ERCOT zone overlays with hover highlighting and lensed (price/SOC) home markers, a canvas flow/dispatch-ripple overlay, an instanced three.js neighborhood stratum (SOC rings, state badges, load-driven window glow) generated per zone for whichever zone sits under the map crosshair (dive chip / double-click / zoom handoff), a grid-events feed derived from the stream, sim-day lighting on both strata, transport controls (pause / 1x / 60x / 3600x / jump-to-next-price-event), fleet dispatch, click-to-inspect, and an offline demo replaying `web/public/traces/demo/`. Panel z-order is a documented contract at the top of `web/src/styles.css`; the Playwright visual spec (`web/e2e/visual.spec.ts`) asserts no interactive control is occluded at its rendered position. The demo trace includes a real recorded fleet dispatch (fired mid-capture by the recorder); the replay transport is a tape deck (pause/resume/setSpeed/seek) and demo dispatch buttons seek to the recorded command. E2E hooks: `window.__batsimMap`, `window.__batsim.store`, `window.__batsim.seekToSimTime(ms)` (replay only). Re-record with `npm run record:demo` (env knobs: RUN_UNTIL, TICKS, HOME_COUNT). TS API types generate from the vendored spec with `npm run gen:client` in `web/` - regenerate whenever `api/openapi.json` changes. Web CI is the `web` job in `.github/workflows/ci.yml` (npm ci, lint, typecheck, vitest, build, Playwright demo-mode smoke).

## Engineering loop

`cargo check --workspace` -> `cargo clippy --workspace --all-targets -- -D warnings` (pedantic denied via workspace lints; curated allows documented in root `Cargo.toml`) -> `cargo test --workspace`. Toolchain pinned 1.83.0 via `rust-toolchain.toml`; dep versions must stay 1.83-compatible (check edition2024 conflicts when bumping; the lockfile pins several transitive crates back for this - see the M2 server commit). Regenerate goldens only with `INSTA_UPDATE=always cargo test -p batsim-core --test golden` and review the diff. The determinism test takes ~2 min in debug.

Contract and E2E verification: `just contract` (schemathesis full check set; per-operation exemptions are documented in `schemathesis.toml`, stream paths are excluded as non-request/response) and `examples/python-e2e/run.sh` (generates a Python client from the live server and drives a 100-home fleet). CI runs fmt/clippy/test plus vendored-spec freshness (`batsim --dump-openapi` diffed against `api/openapi.json`), schemathesis, and the Python E2E.

## Binding design decisions (documented in code)

- D8 (M2): home deletion is tombstoning (`retired` flag), never removal - arena indices key every RNG substream, so removal would re-key the fleet. Dispatch commands carry issuer tags so one command can be retracted without touching others. PV curtailment is a dispatch action in core (lossless at the MPPT).
- D9 (M2): the OpenAPI document is generated by utoipa, then patched as JSON (`build_openapi`) for what derives cannot express: catalog-driven enums, the dispatch-target anyOf, unsigned 64-bit integers, flattened document schemas. The patch must roundtrip through `OpenApi` deserialization (guarded by a lib test).
- D10 (M2): request bodies must be JSON objects (serde accepts positional arrays for structs); query structs use `#[into_params(parameter_in = Query)]` because utoipa defaults to path; every error is an RFC 9457 problem document with a stable SCREAMING_SNAKE code.
- D11 (M2): composition multiplicities are bounded (battery/inverter 1..=16, expansion 1..=10000) and every RNG draw on an untrusted path is panic-free - fuzzed inputs otherwise abort or panic the process.

- D12 (M3): settlement interval energy comes from per-home cumulative meter deltas (`HomeMeters.main`/`batt_ac`) sampled at interval boundaries on the engine thread, never from sampled power x dt. A backtest resets its fleet's homes to freshly composed instances at their existing arena indices before start (`ResetHomes`): same index = same RNG substream, so identical inputs give bit-identical reports (tested), and A/B strategy comparisons share initial conditions. Report provenance is derived from the loaded data rows, never from the request - a synthetic archive cannot yield a `settlement_final` report.
- D13 (M3): the ORDC/RDPA adder split is not ingested in v1 (reports moved behind the data.ercot.com registration wall); adder columns are 0.0 and documented as omitted per the provenance convention. A `Live` PriceSource adapter is deliberately unimplemented (no network on sim paths). Money is f64 end to end; ERCOT constants live only in `config/ercot_rules.v2025.toml` (parsed at runtime, version recorded in every report and manifest).

- `ac_to_dc` is conservation-true (DC delivered = AC x eta); dividing by efficiency on the charge path would invent energy.
- DC-coupled `rte_ac_coupled` = battery-curve product x eta_hyb^2 (grid charge on a hybrid is a double conversion); catalog curves are renormalized so measured round-trip efficiency matches each datasheet figure.
- Standby draw derives from `self_discharge_frac_per_day` and is metered AC-side.
- The ambient feed stands in directly as cell temperature (thermal and degradation models are future work); PV-sourced hybrid charging never crosses the AC battery meter.
- `pv.dc_ac_ratio` is applied as the PV path's AC cap (`kw_dc / dc_ac_ratio`), tighter than the inverter nameplate; the overhang is `pv_clipped`.
- A `DCCoupledHybrid` battery with `integrated_inverter == true` and no declared hybrid gets its `InverterUnit` synthesized from the compatible catalog entry (the PW3 *is* its own hybrid); an explicitly declared hybrid must carry `quantity >= ` the integrated head-unit count or composition errors.
- Inverter `quantity` aggregates by scaling both the AC rating and the efficiency-curve x-axis by N, i.e. N units share the flow equally. Per-module PV units (microinverter / battery-integrated ratings) scale to the array DC nameplate instead of capping it at one unit.
- PV priority at a shared hybrid inverter is enforced in the battery stage by curtailing the hybrid *discharge command* to the AC headroom PV leaves (`batt_clipped`); the inverter stage then treats realized pack DC as non-negotiable and curtails only PV, which is losslessly curtailable at the MPPT. Clip counters are attributed by actual bus share, never by the config flag.
- Every transcendental on a simulation path goes through `batsim-core/src/math.rs` (the `libm` crate), never the `f64` intrinsic methods: platform libms differ by an ulp and the golden traces hash every tick. Correctly rounded ops (`sqrt`, `ceil`, `floor`, `round`, `abs`) stay intrinsic. Golden snapshots are therefore bit-exact across macOS/Linux; regressions here fail CI on the other platform.
